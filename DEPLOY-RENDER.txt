THE KM - RENDER PAR DEPLOY KAISE KAREIN (Hinglish, step by step)
=================================================================

VIEWS RUK GAYE, PHIR EK SAATH AA GAYE? (server so jata hai)
-------------------------------------------------------------
Render free service 15 minute koi visit na aaye to SO JATI HAI. Sote waqt scheduler kuch nahi bhej sakta,
isliye orders ke hisse (legs) ghanton tak ruk jaate hain. Jaise hi koi site kholta hai, server jaag jata hai.

1. ASLI ILAAJ (zaroori): UptimeRobot (free) lagao jo har 5 minute me aapki site ka /tick kholta rahe:
       https://<aapki-render-site>/tick      (jaise https://key-system-4vv8.onrender.com/tick)
   Ise lagane ke baad server sota hi nahi. Bina iske schedule bharosemand nahi chalega.
2. Safety (is ZIP me): agar server kabhi so bhi jaye, to jaagne ke baad jo hisse late ho gaye wo ab
   ek saath nahi jate. Har order ka sirf 1 late hissa lagbhag har 40 second me jata hai; samay par wale
   hisse waise hi time par jaate hain. Isse views dheere-dheere aate hain, 3000 ek saath nahi.
   (Speed badalni ho to Render env: SCHEDULER_LATE_SPACING_SECONDS = 40 ki jagah koi aur sankhya.)
3. Server so gaya tha ya nahi: Render > apni service > Logs me "Service spinning down" ya
   "Your service is live" (jaagne par) wali lines dekho.

KYA FIX HUA
-----------
1. index.html se gate.css aur gate.js ke tags hata diye (ye files repo me thi hi nahi).
   Inhi ki wajah se "Unexpected token '<'" error aa raha tha.
2. build.js ab saari zaruri files dist/ me copy karta hai (auto-key.css, neon.css, auto-admin.html,
   wallet.html, admin.html, panel-config.html, icons, manifest.json...). Pehle sirf 3 files jaati thi.
3. build.js ab check karta hai ki HTML me jo bhi file likhi hai wo sach me maujood hai.
   Kuch missing hua to build FAIL ho jayega (site chupchap toot-ti nahi).
4. server.js: agar koi .js/.css/.png file nahi mili to ab 404 aayega, index.html nahi.
   Saath me: crash-safe API handlers, /healthz, private files (.env, .sql, lib/, api/) block.
5. package.json: javascript-obfuscator ab "dependencies" me hai, taaki Render par build hamesha chale.

DEPLOY KARNE KA SAFE TARIKA (purani site ko haath mat lagana)
--------------------------------------------------------------
Step 1. GitHub par naya branch banao, jaise "fix-deploy", aur ye saari files us branch me upload karo.
        (main branch abhi mat badlo.)

Step 2. Render me NAYA Web Service banao (purana wala mat chhedo):
        - Repo: kshitijM0/kmpremium
        - Branch: fix-deploy
        - Runtime: Node
        - Build Command:  npm install && npm run build
        - Start Command:  npm start
        - Health Check Path: /healthz
        - Plan: Free

Step 3. Environment variables (Render > Environment). Sirf NAAM yahan likhe hain,
        values apne purane Render/Vercel settings se copy karo. Values kisi ko bhejna mat.
          SUPABASE_URL
          SUPABASE_SERVICE_ROLE_KEY
          ADMIN_PASSWORD
          ADMIN_SESSION_SECRET
          PROVIDER_ENCRYPTION_KEY
          KEY_SESSION_SECRET
          UPSTASH_REDIS_REST_URL
          UPSTASH_REDIS_REST_TOKEN
        Agar use karte ho to:
          UPI_ID, UPI_NAME           (wallet deposit)
          LINKVERTISE_ANTI_BYPASS_TOKEN   (free key claim)
          (RENDER_PROXY_URL ko set MAT karo / delete kar do: tab naya built-in scheduler use hota hai)
        Missing variable ho to Render ke logs me "WARNING: these environment variables are not set"
        dikhega (sirf naam, value nahi).

Step 3b. Supabase: NAYE service ko SAME Supabase project se jodo jo purani site use karti thi
        (SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY dono usi project ke hone chahiye).
        SUPABASE_URL aisa hona chahiye: https://xxxx.supabase.co  (end me /rest/v1 ya space nahi).
        SUPABASE_SERVICE_ROLE_KEY = "service_role" key (anon key NAHI).
        NAYA/khali Supabase project mat banao: repo ki SQL files me "orders" table kisi file me
        create hi nahi hoti (sirf alter hoti hai), yaani purane project me wo kisi aur tareeke se bani thi.
        Isliye hamesha purana (chalta hua) Supabase project hi use karo. Wahan purane tables pehle se hain,
        SQL dobara chalane ki zaroorat nahi.
        Table Editor me check karo ki api_providers aur auto_keys dono hain.

        Agar Auto-Admin me "Could not load providers" aaye: Render > Logs me
        "[providers] Supabase error while loading api_providers:" wali line dekho, wahi asli wajah hai.

Step 4. Deploy hone ke baad NAYE URL par ye sab check karo:
        [ ] /healthz  -> "ok" dikhna chahiye
        [ ] Homepage khule, design sahi dikhe
        [ ] Browser console (F12) me koi red error na ho
        [ ] /style.css, /neon.css, /auto-key.css  -> CSS text dikhe (website nahi)
        [ ] /script.js -> JavaScript dikhe
        [ ] /auto-admin khule aur admin login chale
        [ ] Key daal kar key catalog / order test
        [ ] Manual order lagao -> Schedules tab me order dikhe, /tick kholne par {"claimed":...} aaye

Step 5. Sab theek ho to: fix-deploy ko main me merge karo, ya purane Render service ka branch
        change karke fix-deploy/main set karo. Tabhi purana URL (thekm.onrender.com) naye code par aayega.

SETUP: WEBSITE ALAG, ENGINE RENDER PAR
-------------------------------------
Website (frontend)  -> Vercel ya GitHub Pages (jahan chahe)
Engine (Render)     -> server.js: panel PROXY (/proxy) + SCHEDULER (/schedule-order, /orders ...) + Auto-Key API
Naya Vercel proxy (kmpanel-proxy.vercel.app) ab zaroori nahi; chaho to band kar do.

Website kis engine se baat kare: script.js ki line 6 (ENGINE_URL).
  - Render / localhost par site apne aap khud ko use karti hai.
  - Vercel / GitHub Pages par https://thekm.onrender.com use hota hai. Aapka Render URL alag ho to wo URL line 6 me badlo.

Agar website Vercel par hai, to Vercel > Settings > Environment Variables me ye bhi daalo
(taaki Auto orders Render ke scheduler tak pahunche):
    RENDER_PROXY_URL         = https://<aapki-render-site>      (end me / nahi)
    SCHEDULER_SHARED_SECRET  = koi lamba random secret  (Render par bhi SAME daalo)
Render par bhi: SCHEDULER_SHARED_SECRET = wahi secret.
(Vercel ka domain kmpremium.vercel.app pehle se allowed hai. Alag domain ho to Render par
 SCHEDULER_ALLOWED_ORIGINS = https://aapka-domain.vercel.app daalo.)

NAYA SCHEDULER (purane kmpanel.onrender.com ki jagah) - ab server ke andar hi hai
---------------------------------------------------------------------------------
Orders Supabase me save hote hain, isliye server restart ya so jaane par bhi order nahi khote.
Server jaagta hai to har 20 second me due parts (legs) panel ko bhej deta hai.

Step A. Supabase -> SQL Editor -> New query -> supabase/scheduler-schema.sql ka text paste -> Run.
        (Sirf 2 NAYE tables banata hai: sched_orders, sched_legs. Purane tables ko haath nahi lagata.)

Step B. Render > Environment:
          RENDER_PROXY_URL  ->  Render par KHALI rakho / delete karo (set hoga to Auto orders purane URL par jayenge)
          Optional: SCHEDULER_ALLOWED_ORIGINS = https://kshitijm0.github.io,https://aapki-doosri-site.com
                    (GitHub Pages aur thekm.onrender.com pehle se allowed hain)
          Optional: SCHEDULER_TICK_SECRET = koi lamba random secret

Step C. Server ko sone se bachao (Render free service 15 min idle ke baad so jati hai):
        uptimerobot.com par free account -> New monitor -> HTTP(s) -> URL:
            https://<aapki-render-site>/tick          (secret set kiya ho to /tick?secret=AAPKA_SECRET)
        Interval: 5 minutes.
        Isse server jaagta rehta hai aur har 5 min me due parts bhi bhej diye jaate hain.

Step D. Test: bahut chhota manual order lagao (panel connect karke). Phir:
        - Schedules tab me order dikhna chahiye
        - /tick kholo: {"claimed":1,"done":1,...} aana chahiye jab part due ho
        - Panel ke dashboard me order aaya ya nahi dekho

GitHub Pages par: script.js (line 6, ENGINE_URL) me aapki Render site ka URL hona chahiye.

JAANE-ANJAANE BAATEIN
---------------------
- Panel ko standard SMM format me order jata hai: key, action=add, service, link, quantity (comments ho to comments).
  Aapka purana scheduler kuch alag bhejta tha to pehle chhota test zaroor karo.
- Temporary error (rate limit / panel unreachable) par 2 min aur 5 min baad dobara try (total 3 baar).
- Timeout ya samajh na aane wale jawab par dobara try NAHI hota (warna double order lag sakta hai).
  Aise parts Schedules tab me "Failed: n" me dikhte hain; panel me check karo.
- Auto key orders bhi isi scheduler se jaate hain. Scheduler start na ho paye to key ka paisa wapas ho jata hai (pehle jaisa).
- Tests chalane ke liye (computer par): npm install && npm test
